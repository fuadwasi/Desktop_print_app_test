Overview

The Auto Print System provides an end-to-end automated printing solution by integrating your eCommerce storefront (nopCommerce) with physical receipt and document printers via a local desktop printing agent. The system consists of two main components: the Auto Print Agent (nopCommerce Plugin) and the Print Desktop Client (.NET WPF Agent). By leveraging a robust MQTT broker connection, documents—such as packing slips, POS receipts, and kitchen slips—are automatically routed from the cloud to the designated hardware printers with zero data-at-rest.

System Architecture & Components

  • nopCommerce Plugin (Auto Print Agent): Captures store events (e.g., Order Paid), creates print jobs, and fires MQTT events containing the print directives. It manages store-to-printer mappings and device account IDs.
  • Print Desktop Client: An enterprise-grade, profile-based WPF application running locally. It maintains parallel, persistent MQTT connections, consumes the print events, requests the document payload (PDF) from the plugin API, and silently prints it to the mapped local or network printer.

Key Features

  • End-to-End Automation: Trigger automatic printing of critical documents upon specific store events without manual intervention.
  • Multi-Profile Execution: The desktop client can manage and run multiple active printer-integration profiles simultaneously on the same machine.
  • Zero Data-at-Rest: PDFs are downloaded to a temporary location, printed silently to the spooler using PdfiumViewer, and immediately wiped from the drive.
  • Secure Communication & Storage: Utilizes MQTT with username/password authentication, downloads via secure HTTP APIs, and encrypts local client secrets using Windows DPAPI.
  • Remote Revocation (Self-Wipe): If the plugin revokes access or returns a 401 Unauthorized, the desktop client automatically deletes its encrypted secrets and disables the profile to secure client data.

Requirements

  • nopCommerce 4.90.3
  • .NET 9.0 (Server and Client)
  • An active MQTT Broker (e.g., Mosquitto, EMQX)
  • Windows 10/11 for the Print Desktop Client

Installation

Phase 1: nopCommerce Plugin

  1. Download the plugin archive.
  2. Extract the contents and copy the NopStation.Plugin.Misc.AutoPrintAgent folder into your nopCommerce Plugins directory.
  3. Log in to your nopCommerce admin area and navigate to Configuration > Local plugins.
  4. Find Auto Print Agent in the list and click Install.

Phase 2: Print Desktop Client

  1. Deploy the single-file standalone executable (PrintDesktopClient.exe) to your target Windows machine.
  2. Launch the application. It will open the main configuration UI.
  3. The client can be configured to run minimized to the system tray for silent background operation.

Configuration

Plugin Configuration (nopCommerce)

Navigate to Nop Station > Auto Print Agent > Configuration.

Field Description
Enable auto print Globally toggle the auto-printing functionality on or off.
Trigger events Select the specific nopCommerce events that will trigger a print job.
MQTT Broker URL The URL/IP address of your MQTT broker used to dispatch print messages.

Desktop Client Configuration

  1. Open the Print Desktop Client.
  2. Create a new Profile and enter the MQTT Broker credentials matching the plugin settings.
  3. Enter the API Base URL pointing to your nopCommerce instance.
  4. Enter the unique Device Account ID and API Secret generated by the nopCommerce plugin.
  5. Select the local target printer from the dropdown.
  6. Click Test Connection to validate HTTP and MQTT connectivity, then Save.

How It Works (The Full Pipeline)

  1. Event Trigger: A customer action (e.g., placing an order) fires an event in nopCommerce.
  2. Job Creation: The Auto Print Agent plugin captures this, generates the document, creates a Print Job, and dispatches a lightweight MQTT message to the specific Device Account topic.
  3. Message Reception: The Print Desktop Client's MqttListenerService receives the command via its persistent MQTT connection.
  4. Payload Retrieval: The client executes an API request back to nopCommerce (using secure headers) to download the raw PDF bytes.
  5. Silent Printing: The client saves the PDF temporarily, uses PdfiumViewer to spool the job directly to the configured Windows printer queue, and deletes the temporary file.
  6. Status Update: The client sends an API callback to nopCommerce marking the Print Job as successfully printed or failed.

Troubleshooting

Print Jobs are stuck in "Pending"

Ensure both the plugin and the desktop client are connected to the same MQTT Broker. Check the client logs (located at %LOCALAPPDATA%\PrintDesktopClient\logs\) for MQTT connection errors or API download failures.

Device Status is showing as Offline

Verify that the Print Desktop Client is running and its profile is enabled. The client maintains an active MQTT session and sends periodic status updates.

FAQs

Can I route kitchen slips to the kitchen printer and packing slips to the warehouse?

Yes. In nopCommerce, navigate to Store Printer Mappings to define document routing. Then, set up two separate profiles in the Print Desktop Client—each mapping a specific Device ID to the respective physical printer.

Is my API secret secure on the local machine?

Yes. The Print Desktop Client utilizes the Windows Data Protection API (DPAPI) to encrypt your MQTT passwords and API secrets before saving them to disk.
